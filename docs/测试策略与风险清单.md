# 测试策略与风险清单

更新日期：2026-09-10　被测系统：mall-tiny 权限管理（commit a81ec47）

## 一、测试范围

**纳入**：用户注册/登录/Token 刷新/信息查询/登出；用户查询/更新/状态/密码/删除；
角色 CRUD 与用户角色分配；菜单 CRUD 与树结构；资源分类与资源 CRUD；角色资源分配；
JWT 鉴权与 401/权限语义；MySQL 落库一致性；Redis 缓存生成/失效/重建。

**暂不纳入**：前端 UI 自动化；Java 单元测试；CACHE-04（Redis 停机降级，属探索型
用例，需要停/启服务的管理员权限，暂缓至具备隔离 CI 环境后执行）；漏洞利用类安全测试。

## 三、用例设计方法

1. **预期来源五层**：需求文档 → 接口文档 → 源码 → 首次探索实测 → 行业惯例。
   文档缺失时以实测为准，但断言依据必须可追溯（探索记录）。
2. **探索 → 判断 → 固化**：实测观察行为 → 用业务/安全常识判断合理性 →
   合理行为固化为回归断言，不合理行为记录缺陷（禁止为绿灯改断言）。
3. **四层断言**：HTTP 状态码 + 业务码 + 关键字段 + 数据层（DB/Redis），
   防止"HTTP 200 + 业务失败"型假绿。
4. **参数化边界**：断言同构的用例做数据驱动（登录失败矩阵、非法 JSON 六形态、
   损坏 Token 四形态）；断言异构的保持独立函数。
5. **多身份**：访客（无 Token）/普通用户（qa_user）/管理员（admin_token），
   同一接口用不同身份调用构成权限用例组。

## 四、数据管理

- 所有测试数据 `qa_{日期}_{随机}` 前缀，严禁修改/删除种子数据
- 清理顺序：先关系表后主体表；fixture yield teardown 保证失败也清理；
  清理操作全部幂等（按唯一键 DELETE / EXISTS 无关删除）
- 用户删除同步清理其 Redis 缓存键（夹具兜底）

## 五、环境管理

- 本机直跑：Windows MySQL 5.7 服务 + Redis 5.0 服务 + 本机构建的 jar
- 容器化：docker compose（mysql:5.7 + redis:6.2 + temurin-8jre 应用镜像），
  健康检查通过后应用才接受流量；初始化冻结自被测源码固定 commit
- 已知环境差异已修复并固化：init SQL 字符集（SET NAMES utf8mb4）、
  容器 JVM 中文 locale（JAVA_TOOL_OPTIONS）、redis-py 8.x 需 protocol=2
  （服务器为 Redis 5.0，不支持 HELLO/RESP3）

## 六、CI/CD

push 到 main / PR 自动触发：双仓库检出 → Maven 构建 jar → 应用镜像构建 →
Compose 起环境 → 健康探测 → 全量 pytest → JUnit/Allure 归档。
失败即 Job 失败，形成质量门禁；报告 Artifact 无论成败均上传。

## 七、已知限制

1. CACHE-04（Redis 停机降级）为探索型用例，需停/启服务的管理员权限，
   本机执行风险高，暂缓至隔离 CI 环境执行
2. 性能基线为单机学习环境数据，不代表生产容量结论
3. 种子用户 admin 的密码已重置为测试口令，仅限本地学习环境使用
